# 本地运行说明

先运行单元测试，再执行演示命令。演示从干净临时目录发起真实请求并处理响应，不需要外部站点。
常规导入失败时返回非零退出码，事务中的原文和记录会一起回滚，可保留源文件再次处理。
查询模式只读取当前数据库，不会补采或删除来源数据。需要长期保留证据时，请备份整个数据库。
本地响应服务支持状态码、响应头、文本或 base64 字节正文；未配置路径返回未找到。
每条路径的脚本独立推进，最后一个响应会重复；可借请求记录核对调用顺序。
数据文件的路径均相对项目根目录，修改工作目录前请确认输入和数据库参数。

## 批量自动操作的运行处置

每条录入以“审批单号 + 内容摘要”确定业务身份，状态机的状态含义与处置方式：

| 状态 | 含义 | 操作员处置 |
| --- | --- | --- |
| PENDING | 已登记，草稿尚未保存 | 重跑 `batch` 即可，草稿保存是幂等的 |
| DRAFTED | 草稿已保存并核对摘要 | 重跑 `batch` 会先落提交意图再单次提交 |
| SUBMIT_UNCERTAIN | 提交意图已落库，受理结果未知 | 只能 `batch --recheck`，禁止重提 |
| VERIFIED | 已核实远端回执（直连或查询） | 无需处置 |
| NEEDS_MANUAL | 同单号不同摘要等业务冲突 | 登录门户人工核对，不要自动覆盖 |
| BLOCKED_MANUAL | 人工确认/验证码/页面结构变化 | 排除障碍后重跑，系统不会代确认 |

批次停止原因会随报告的 `stop_reason` 返回：`SESSION_EXPIRED` 表示需要人工重新登录，
随后用 `--renew-session` 恢复；锁冲突（退出码 4）表示已有同事在跑同一批次，不要强杀锁文件。
`SUBMIT_UNCERTAIN` 是安全状态而非失败：门户未承诺幂等，查不到不等于没办过，
重复执行 `--recheck` 不会产生第二条申请；只有门户明确 `not_found_is_final=true` 时
才允许退回草稿阶段重走流程。
审计日志在 `status` 命令的 `journal` 中，记录每条迁移的事件、前后状态与时间，
不包含 cookie、token 等会话值；若日志中出现 `***REDACTED***`，说明脱敏过滤器已生效。
